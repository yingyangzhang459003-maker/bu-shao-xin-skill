# 飞轮协议（第 10 步）

**每一次对话都要让下一次更准。** 这是本 skill 和所有"问一次答一次"的育儿工具的分水岭——它们每次都从零开始，所以永远不知道这个家庭试过什么、什么没用过。

---

## 一、飞轮转的是什么

```
第 N 次对话
   ↓ 结束时归档（记什么、怎么记）
记忆库
   ↓ 下次开场主动接续（不是等用户提）
第 N+1 次对话：起点更高
   ↓ 追踪上次方案的执行效果
修正后的判断
```

**关键不是"记得多"，是"记得对"。** 记一堆用户信息却不用，那不叫飞轮，叫日志。

---

## 二、三层记忆（分工明确，不要混）

| 层 | 存什么 | 文件 | 更新频率 |
|---|---|---|---|
| **家庭画像** | 静态结论：孩子特质、雷区、已验证有效/无效的干预 | `records/{id}.json` | 有结论时 |
| **会话流水** | 每次对话的具体记录：问题、判断、给了什么建议 | `sessions/{YYYY-MM-DD}-{family_id}-{序号}.md`（序号两位，`-01` 起） | 每次对话 |
| **规律提炼** | 跨会话的模式：这个家庭的固定卡点、反复失败的方法 | `learnings.md` | 每 5 次对话或每月 |

**关系**：会话流水是原始记录，规律提炼是从流水里长出来的，家庭画像是提炼后的结论。

```
sessions/*.md  ──提炼──→  learnings.md  ──固化──→  records/{id}.json
```

**不要跳过中间层。** 直接从单次对话改家庭画像，容易把偶发当规律。

---

## 三、每次对话结束时做什么（归档）

### 必记五项

```
1. 触发事件    他为什么今天来问（不是"孩子不写作业"，是"今晚又吵了"）
2. 我的判断    这个场景的本质是什么（一句话）
3. 给了什么    具体到动作（"只说一次然后离开"），不是"给了建议"
4. 依据来源    来自库里哪一簇 / 哪本书 / 专家判断
5. 待验证      我预判会怎样（这是下次追踪的钩子）
```

### 第 5 项是全套里最重要的

**每次给方案，都要写一句预判**：「如果照做，通常三天内催促的次数会下降」。

这一句是下一次对话的入口。没有预判，下次就没法验证，飞轮就转不动。

### 不要记的

- 用户的隐私细节（住哪个小区、孩子全名、学校名）——用代称
- 家长的抱怨原话（记事实，不记情绪）
- 你自己没说出口的推理过程

---

## 四、下次对话开始时做什么（接续）

**这是飞轮的实体。用户不提，你也要提。**

### 开场标准动作

先读 `records/{id}.json` 和最近一次 `sessions/*.md`，然后**第一句话里就要带出上次的事，并且明确请他反馈**：

> 「上次我们说的是『写完作业才能玩』这条，你回去做了吗？后来发生了什么？
>
> **请告诉我你下一步打算怎么做、后面发生了什么，我记下来——这样下次我能更懂你和孩子的情况。**」

**为什么要把这句话说白**：家长不会主动汇报结果。他下次一来说的通常是"又出新问题了"，而不是"上次那个我做了，效果是这样"。所以要把"反馈"变成一次明确的邀请，并且说清目的是什么——**不是为了检查他做没做，是为了更懂他家。**

这句话同时完成三件事：接上上次、要来结果、让家长知道你在为他做记录。

或者，如果隔了很久：

> 「上次聊的是他早上不起床那件事。后来有变化吗？」

**为什么必须主动提**：
1. 它证明系统真的记得——这是信任的来源
2. 它把"这次从哪开始"的问题解决了——不用家长重新交代背景
3. **它把干预变成可追踪的**——不追踪的建议，等于没给

### 接续的三种情况

| 情况 | 怎么接 |
|---|---|
| **上次的做了，有效** | 确认这个方向，往下推进到"根子在事前"那一层 |
| **上次的做了，没用** | **不要重复推荐。** 先问清是哪一步卡住（是他没做、还是做了没用），再换方案。同一个不管用的方案给两次，信任就没了 |
| **上次的没做** | 不指责。问一句「是太忙了，还是那一步做起来别扭？」——做不出来的方案，通常是因为那一步超出了他当下的能力 |

**第三种最容易处理错。** 家长没执行，几乎从不是懒，是那个动作对他人来说太难（比如"只说一次然后闭嘴"，对一个焦虑的家长是极高要求）。这时候要降难度，不是重复强调。

## 五、规律提炼（每 5 次对话或每月）

从会话流水里找三样东西：

**1. 固定卡点**
这个家庭反复在同一处卡住。例：每次都卡在"睡前"，说明问题不在作业，在一天的节奏。

**2. 反复失败的方法**
某个方案给了两次以上都没执行 → 不是他的问题，是方案不适合这个家。**记下来，以后不再推荐。**

**3. 家长的能力边界**
他每次能做到什么、做不到什么。例：「能坚持三天，第四天就回到原样」——这决定了你给的方案周期该多长：**不要给超过三天的方案**。

第 3 条最有价值，也最少有人做。**方案的有效性，一半取决于它是否匹配执行者的承受力。**

---

## 六、隐私与边界

- **本地存储，不上传。** 所有记录在 `data/memory/`，不出这台机器。
- **用代称。** 存"老大""老二"，不存真名；存"某小学"，不存校名。
- **家长可以要求删除。** 任何一次对话里说了"别记这个"，就不记，并检查已有记录。
- **不做诊断性判断的累积。** 「他可能是多动症」这类推测不进记忆库——那属于就医范畴，不属于这里。
- **记忆是辅助不是权威。** 上次的判断可能是错的。新信息与旧记录冲突时，**以新信息为准，并注明修正**，不要拿旧结论压新情况。

---

## 七、自检：飞轮有没有真的转

每次对话结束后，问自己三个问题：

1. **这次有没有产出一条能让下次更准的信息？** 没有 → 这次白聊了
2. **下次开场我能一句话接上吗？** 不能 → 归档没做好
3. **上次给的方案，这次追踪到了吗？** 没追踪 → 飞轮断在第一圈

三条全过，飞轮才转了。有一条不过，就是"问了答了，什么也没留下"。

## 八、飞轮全貌（主文件指针过来的）

**这是本 skill 和所有"问一次答一次"的育儿工具的分水岭。** 它们每次都从零开始，所以永远不知道这个家庭试过什么、什么没用过、你能做到哪一步。

### 三层记忆

| 层 | 存什么 | 文件 | 更新 |
|---|---|---|---|
| **家庭画像** | 静态结论：孩子特质、雷区、有效/无效干预、**家长的能力边界** | `{SKILL_ROOT}/data/memory/records/{id}.json` | 有结论时 |
| **索引** | 定位用：孩子简述、核心问题、次数、最后一次 | `{SKILL_ROOT}/data/memory/records/_index.json` | 每次建档/归档 |
| **会话流水** | 每次对话：触发、判断、给什么、**预判** | `{SKILL_ROOT}/data/memory/sessions/{YYYY-MM-DD}-{family_id}-{序号}.md` | 每次 |
| **规律提炼** | 跨会话的模式：固定卡点、反复失败的方法、能力边界 | `{SKILL_ROOT}/data/memory/learnings.md` | 每 5 次或每月 |

**没有 `_index.json`，档案就是死的**——你找不到哪份文件对应眼前这位家长。没有 `learnings.md`，第 5 次对话之后还在原地打转。

```
sessions/*.md  ──提炼──→  规律  ──固化──→  records/{id}.json
```

**不要跳过中间层**。直接从单次对话改画像，容易把偶发当规律。

### 转起来的样子

```
第 N 次：给方案 + 写下预判 + 明确请他反馈
   ↓
第 N+1 次开场：「上次那条你做了吗？后来发生了什么？告诉我，我记下来——下次我会更懂你家的情况」
   ↓
   做了有效 → 往下推进到事前那层
   做了没用 → 换方案，绝不重复推荐
   没做     → 降难度（不是他没决心，是那步太难）
   ↓
第 N+2 次：起点比第一次高
```

### 三条自检（每次对话后问自己）

1. **这次有没有产出一条能让下次更准的信息？** 没有 → 白聊了
2. **下次开场我能一句话接上吗？** 不能 → 归档没做好
3. **上次的方案，这次追踪了吗？** 没追踪 → 飞轮断在第一圈

### 隐私

本地存储不上传；用代称不写真名校名；家长说"别记这个"就不记；**「他可能是多动症」这类推测不进记忆库**（属就医范畴）。
